## 3. 결정 가이드

- **혼자 쓰려고, 신간을 추적하거나 내 서재를 관리하려고** → **Plan A**. 가장 빨리 쓸 수 있다. 나중에 B로 옮길 수 있게 컬럼 이름을 B와 맞춘다.
- **한국 도서 "전체" DB가 필요하고, 나중에 공개하거나 상업적으로 쓸 수도 있다** → **Plan B**. CC0 중심이라 상업 여부를 아직 정하지 않았어도 안전하다.
- **사용자에게 검색 서비스를 공개하고 싶고, 소장 도서관·대출 가능 여부 같은 기능이 중요하다** → **Plan C**. 다만 B를 먼저 끝내야 하고, 정보나루 승낙과 Kakao 약관 문제를 감수해야 한다.
- **서비스보다 "무엇이 나오고 무엇이 읽히는가"를 연구하거나 글로 쓰고 싶다** → **Plan D**. 서비스 운영 부담이 없다. 대출 데이터 보관 승낙은 필요하다.
- **표지 이미지와 책소개가 핵심 기능이다** → 어느 계획으로도 **합법적으로 쌓기 어렵다**.
  - Seoji 표지는 대부분 비어 있다.
  - 정보나루 표지는 비영리 화면 표시에만 쓸 수 있다.
  - Kakao는 실시간 표시만 된다.
  - 요구 사항을 다시 검토해야 한다.

## 4. 추천: **Plan B를 기본으로 하고, 목적에 따라 C나 D를 위에 얹는 단계적 경로**

**이유**
1. **라이선스가 가장 깨끗하다.** 핵심 데이터가 LOD(공공누리 1 + CC0)이므로, 아직 정하지 않은 질문(상업적 이용 여부, 공개 여부)에 어떻게 답해도 다시 만들 필요가 없다. A는 Seoji만 쓰는데, Seoji는 명시적 약관이 없다.
2. **커버리지를 확보할 수 있는 유일한 경로다.** 과거 도서를 대량으로 받을 방법은 LOD 덤프뿐이다. Seoji로 과거를 얼마나 백필할 수 있는지는 검증되지 않았다.
3. **상업 API가 사라지는 추세에 강하다.** Naver와 알라딘이 종료됐고 Kakao는 저장을 금지한다. 공공 데이터 중심 설계는 이런 변화에 흔들리지 않는다.
4. **확장의 기반이 된다.** B의 bronze/silver/gold와 `field_provenance`는 C(정책 계층과 검색 엔진 추가)와 D(bronze를 Parquet으로 내보내기)의 공통 토대다. A의 수집기와 정규화 모듈은 B에 그대로 들어간다.
5. **규모가 부담스럽지 않다.** 400만 건 수준은 Postgres 한 대로 충분하다. 어려운 부분은 크기가 아니라 한국어 검색 품질과 병합 규칙인데, B가 정확히 그 부분을 다룬다.

**권장 순서**
1. **지금 바로**: NLK Open API 키를 신청한다. 승인 기간을 알 수 없으므로 가장 먼저 한다. LOD 일반도서 샘플과 덤프도 받는다.
2. **1~2주차**: Seoji PoC로 page_size 최대값, 필터 없는 질의 허용 여부, 하루 건수, 같은 ISBN 중복 빈도를 확인한다. LOD 매핑 명세를 쓴다. 이 단계의 결과는 A에서도 B에서도 그대로 쓸 수 있다.
3. **3~6주차**: B의 핵심(M2~M8)을 만든다.
4. **이후**: 목적에 따라 C(서비스)나 D(분석)를 얹는다. 정보나루 승낙은 1단계와 함께 미리 요청해 둔다.

**단서**: 목적이 "개인 서재/신간 알림"으로 확정되어 있다면 B는 과하다. **A로 시작한다.**

## 6. 모든 계획에 공통인 설계 원칙

- **edition은 ISBN-13으로 키를 잡는다.** ISBN-10은 978 접두에서만 파생한다(979-11에는 ISBN-10이 없다). 체크 숫자를 검증하고, 실패한 값은 격리한다.
- **부가기호 5자리를 독자대상, 발행형태, 내용분류(KDC 주류·강)로 나눠 저장한다.** 출판사가 스스로 신고한 값이라 힌트로만 쓴다. 세트 부가기호는 2번째 자리가 4다.
- **세트(SET_ISBN)와 총서(SERIES_TITLE)를 다른 엔티티로 다룬다.** 기여자는 역할(`role`)과 원문 역할어(`role_raw`)를 함께 저장한다.
- **원본(raw)을 항상 보존한다.** 병합 규칙을 바꿔도 API를 다시 부르지 않고 재계산할 수 있어야 한다. 인증키는 원본에도 로그에도 남기지 않는다.
- **텍스트는 NFC로 저장하고, 비교 키는 NFKC + casefold로 만든다.** 한자 병기와 권차·판차 표지는 비교 키에서 분리한다.
- **ISBN이 다른 레코드를 하나의 edition으로 합치지 않는다.** 같은 ISBN에 다른 기관 레코드가 붙으면 충돌로 표시한다.
- **저장할 수 없는 소스(Kakao, 승인 전 정보나루)의 데이터는 정본 DB와 검색 인덱스에 들어가지 않는다.**
